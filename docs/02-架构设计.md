# DH2 架构设计

文档版本 v1.2 | 架构师维护,开发 Agent 不得直接修改(变更须经审核流程,见 03 文档)

## 1. 设计原则

1. **纯外部**:只"看屏幕 + 发消息",不碰进程内存与网络封包(红线见 01 文档)。
2. **模板化**:游戏内容(坐标、文案、NPC、流程)全部配置化,不硬编码;游戏改版只改模板不改代码。
3. **宁停不错**:识别低置信度 → 暂停并告警,绝不盲目点击;每个动作有后置验证。
4. **可降级**:后台消息不可用则降级焦点轮转;单开跑通再上五开。
5. **可测**:核心逻辑不依赖真实游戏,基于 MockGame 与录制回放测试。

## 4. 运行时与并发模型

- 单进程 Generic Host,DI 容器装配全部服务。
- 每个游戏窗口一个 `ActorSession`,各自运行独立的**感知循环** `Task`:截屏 → ROI 识别 → 场景分类 → 发布场景事件。
- 事件流解耦:感知循环是生产者,任务 FSM 与 Guardian 是消费者;Guardian 以**最高优先级**插队消费弹窗/掉线事件。
- 帧率策略:常态 1~2 FPS;关键等待(战斗结束、过图、寻路到位)提至 5~10 FPS,由原子操作显式声明。
- 五开 = 5 个 ActorSession 真并行(.NET 无 GOL 限制),串行识别调度可配(性能兜底)。

## 5. 感知层设计

### 5.1 ROI 分区(锚点相对坐标)

| ROI | 内容 | 用途 |
|---|---|---|
| 任务追踪栏 | 当前任务条目、剩余次数 | 触发寻路、OCR 任务类型 |
| 对话区 | NPC 对话、选项按钮 | 对话推进、任务接交 |
| 战斗指令区 | 自动战斗按钮、回合数、法术栏 | 战斗控制 |
| 小地图 | 角色位置、坐标 | 卡寻路检测 |
| 血蓝条 | 百分比 | 自动补药 |
| 中央提示区 | 完成提示、错误框 | 任务完成判定 |

- 每个 ROI 的位置 = 锚点模板匹配结果 + manifest 中登记的偏移;
- 状态机节点声明订阅哪些 ROI,未订阅的 ROI 不参与识别(压 CPU)。

### 5.2 模板库与 manifest

```
templates/
└─ {profile}/                 # 分辨率+主题档案,如 std_1280x720
   ├─ manifest.yaml
   └─ png/ *.png
```

manifest 条目字段:`key`(逻辑名)、`file`、`threshold`(默认 0.85)、`clickOffset`(匹配中心到点击点的偏移)、`roi`(所属 ROI)、`since`(游戏版本标记)。加载后不可变快照,支持热重载。

### 5.3 场景分类器(优先级链)

`掉线/登录 > 异常弹窗 > 战斗中 > NPC对话 > 寻路中 > 地图待机`,每个场景 1~2 个特征模板判定,输出 `SceneState` 事件。分类结果是所有决策的前置。

### 5.4 OCR 策略

- 系统 Windows.Media.Ocr 起步(零依赖,中文语言包);
- 任务文案/次数等难点场景升级 PaddleOCR ONNX 模型;
- 纯数字(次数、血蓝)优先用数字模板匹配,更快更稳。

## 6. 执行层设计

- **窗口绑定**:启动时按 进程名+窗口标题规则 枚举并绑定 5 客户端;角色绑定用 OCR 角色名或用户手动排序。
- **后台输入**:`PostMessage(WM_LBUTTONDOWN/UP)` + 客户区坐标(`lParam = y<<16 | x`),窗口无需前台焦点 → 五开可并行。**M0 真机验证此项,不通过则全局降级。**
- **焦点轮转降级**:`SetForegroundWindow` + `SendInput`,时间片逐窗激活操作,慢但通用;通过 `IInputDriver` 抽象,运行时按配置切换,上层无感知。
- 操作带基础间隔(稳定性需要,非拟人化目的);拖拽(地图移动)走 WM_MOUSEMOVE 序列。

## 7. 行为层设计

原子操作契约(每个操作 = 前置检查 → 执行 → 后置验证 → 失败重试):

```csharp
public interface IAtomicAction
{
    string Key { get; }
    Task<bool> PreconditionAsync(ActorSession s, CancellationToken ct);
    Task ExecuteAsync(ActorSession s, CancellationToken ct);
    Task<bool> VerifyAsync(ActorSession s, CancellationToken ct);
    int MaxRetries { get; }          // 默认 3
}

public sealed record ActionResult(bool Success, int Attempts, string FailReason);
```

原子操作清单(随迭代扩充):`pathfind_to`(点任务栏触发游戏寻路,含卡寻路检测重发)、`click_ui`、`talk_npc`、`dialog_next`、`battle_auto`、`buy_item`、`submit_item`、`use_medicine`、`open_panel`/`close_panel`。

## 8. 任务引擎(FSM + YAML DSL v1)

节点 = 场景 + 动作 + 转移条件;支持分支、循环、子流程调用:

```yaml
task: shimen            # 师门
version: 1
entry: accept
max_loops: 20
nodes:
  accept:               # 场景=待机,动作=点任务栏寻路找师父
    action: pathfind_to
    args: { target: tracker }
    on_done: parse_type
    on_fail: guardian_recover
  parse_type:
    action: ocr_task_type
    branches:
      - when: type == battle
        goto: battle_flow
      - when: type == fetch
        goto: fetch_flow
      - else: visit_flow
  ...
  loop_check:
    action: check_counter
    branches:
      - when: done
        goto: finish
      - else: accept
```

v1 语法在 M1b 技术设计中定稿,引擎以解释器实现(非代码生成);YAML 无法表达的复杂逻辑允许内嵌 C# Script 节点(需审核批准)。

## 9. 编排层设计(五开)

- **Leader-Follower**:Leader(队长窗口)跑完整 FSM;Follower 只执行镜像指令子集(寻路点击、对话确认)。
- `BroadcastAsync(action, args)`:按窗口顺序下发后台消息,逐窗等待后置验证。
- `AsyncBarrier(state)`:进战斗、过图等同步点,等待全部窗口到达目标场景,超时交 Guardian。
- Follower 异常由 Guardian 独立恢复后重新入队,不阻塞 Leader。
- **周常调度**(M4):`schedule.yaml` 周历 + Quartz.NET,进度落 SQLite,断点续跑。

## 10. Guardian 设计

| 守护项 | 触发条件 | 处置 |
|---|---|---|
| 弹窗 | 优先级链命中"弹窗"场景 | 分类:公告/邮件/错误 → 关闭或按策略确认,记录 |
| 卡死 | 场景状态或小地图位置 N 秒不变(N 可配,默认 30s) | 恢复梯次:开关面板 → 重寻路 → 界面重置 → 标记失败跳过 |
| 掉线 | 命中"登录/掉线"场景 | 重连流程:登录 → 选角 → 重新组队归队 |
| 战斗超时 | 战斗场景超过 M 回合 | 强制逃跑/结束,记录 |
| 资源异常 | 背包满、银两不足 | 暂停 + 告警推送 |
| 低置信度 | 匹配分低于阈值下限 | 冻结该 Actor 全部输入,截图存档,推送告警 |

## 11. 数据层(SQLite)

```sql
CREATE TABLE run_log(
  id INTEGER PRIMARY KEY, ts TEXT NOT NULL, actor TEXT NOT NULL,
  task TEXT, node TEXT, event TEXT, detail TEXT);

CREATE TABLE task_progress(
  id INTEGER PRIMARY KEY, week_start TEXT NOT NULL, actor TEXT NOT NULL,
  task_type TEXT NOT NULL, done_count INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'pending', updated_at TEXT,
  UNIQUE(week_start, actor, task_type));

CREATE TABLE item_log(
  id INTEGER PRIMARY KEY, ts TEXT, actor TEXT, item TEXT,
  count INTEGER, source TEXT);

CREATE TABLE error_snapshot(
  id INTEGER PRIMARY KEY, ts TEXT, actor TEXT, image_path TEXT, reason TEXT);
```

## 12. 可观测性

- Serilog 结构化日志,`actor`/`task`/`node` 作为 scope 属性;
- 控制台(M4 前):实时输出每 Actor 当前场景与 FSM 节点;
- 告警:Bark / Server酱(掉线、低置信度冻结、任务失败、资源异常);
- 异常必存档:截图 + 上下文写 error_snapshot。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 后台 PostMessage 游戏不响应 | M0 真机验证先行;降级焦点轮转方案已预置 |
| 游戏改版 UI 变化 | 模板版本化 + DH2.Annotator 标注工具,维护成本小时级 |
| 识别误判 | 阈值 + 后置验证 + 宁停不错原则 |
| 五开 CPU 开销 | ROI 裁剪、按需订阅、低帧率、串行识别调度可配 |
| 封号 | 无法根除;自用、小号先验证(用户决策) |
