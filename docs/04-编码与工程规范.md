# DH2 编码与工程规范

适用于全部开发 Agent 提交的代码。审核门禁 G3 依据本文档。

## 1. 工程约定

- TFM:`net10.0-windows`;`<Nullable>enable</Nullable>`、`<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`、`<LangVersion>latest</LangVersion>`;
- 所有项目启用 `.editorconfig`(M0 建立,风格以 IDE 默认 C# 约定为基线,4 空格缩进);
- 公共 API 用 XML 文档注释(`/// <summary>`)标注用途与线程安全性;
- 格式门禁:`dotnet format --verify-no-changes` 必须通过。

## 2. 命名与结构

- 项目/目录/命名空间三者一致(`DH2.Core.Models` ↔ src/DH2.Core/Models/);
- 接口 `I` 前缀;异步方法 `Async` 后缀;P/Invoke 类统一 `static partial class NativeMethods`,方法名保留 Win32 原名;
- 一个类一个职责;超过 300 行的实现类需在自检报告说明。

## 3. 异步与并发

- 所有 I/O(截屏、输入、等待轮询)异步化,`CancellationToken` 必须贯穿传递,禁止吞掉;
- 禁止 `.Result` / `.Wait()`(仅 Main 入口与测试断言允许);
- 轮询等待统一使用 `WaitUntil(predicate, interval, timeout, ct)` 工具方法(DH2.Core 提供),不得散落手写 Thread.Sleep 循环;
- ActorSession 内状态只由其感知循环与执行管线串行访问,跨 Actor 通信用消息(Channel),不加全局锁。

## 4. 异常与结果

- 原子操作/识别方法**不抛业务异常**,返回结果对象(`ActionResult` / `MatchResult`);
- 仅基础设施错误(文件缺失、句柄失效)抛异常,由宿主统一兜底记录;
- `AppDomain.UnhandledException` 与 `TaskScheduler.UnobservedTaskException` 必须挂接 Serilog 落盘。

## 5. 日志

- Serilog,注入 `ILogger<T>`;
- 每条日志带 scope 属性:`actor`(窗口标识)、`task`、`node`;
- 级别:`Debug`=逐帧识别细节,`Information`=节点转移/任务事件,`Warning`=重试与恢复,`Error`=任务失败与守护触发;
- 禁止 `Console.WriteLine`(CLI 程序的用户面输出除外,须与日志区分)。

## 6. 配置

- 全部配置 YAML(`configs/`),用 Options 模式绑定 + 启动时校验,校验失败拒绝启动并输出明确错误;
- 禁止散落的魔法数字:阈值、超时、坐标偏移全部入配置或 manifest;
- 提供 `configs/*.example.yaml` 样例入仓,真实配置(含账号角色名)`configs/local/*.yaml` 不入仓(gitignore)。

## 7. 测试

- xUnit;测试项目 `tests/DH2.Tests`,目录镜像被测项目;
- 命名:`方法名_条件_期望结果`;每个公共类至少覆盖:正常路径、边界、失败路径;
- 需要游戏的逻辑必须通过接口抽象(MatchResult/Frame 等可由 MockGame 或金样本提供),单测禁止依赖真实窗口句柄;
- 覆盖率:核心项目(Core/Vision/Tasks/Guardian)行覆盖 ≥ 70%(coverlet 统计)。

## 8. 红线相关编码禁令(重申)

禁止引入或声明:进程内存读写、远程线程、全局钩子、网络封包拦截、驱动加载相关的任何 P/Invoke、NuGet 包与代码。详见 01 文档第 3 节。

## 9. 提交规范

见 03 文档第 7 节;每次提交须可独立 build 通过。
